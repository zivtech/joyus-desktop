# Implementation Plan: Managed Git Sessions

**Branch**: `006-managed-git-sessions` | **Date**: 2026-03-19 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `kitty-specs/006-managed-git-sessions/spec.md`

## Summary

Add a git management layer to the Joyus Desktop companion that serves non-developers (full automation, no git terminology) and developers (advisory signals, opt-in only). On first file modification in a git repo, the sidecar creates an isolated git worktree and persists a `TaskBranch` record. A 3-signal drift detector monitors the session and surfaces tiered intervention when context diverges. A new `/sessions` page in the React UI exposes all task branches with resume/cleanup/status actions. Detection uses a hybrid approach: `PostToolUse:Write` IPC hook (primary) + 10s `git status --porcelain` poll (fallback).

## Technical Context

**Language/Version**: TypeScript 5.8+, Node.js 24, ESM-only
**Primary Dependencies**: `node:sqlite` (built-in, for TaskBranch store); native `git` CLI via `execGit` injection; Tauri v2 IPC (existing); React 18 + React Router (existing UI)
**Storage**: New `~/.joyus/session-manager.db` SQLite file (separate from `replay-cache.db`)
**Testing**: Vitest; real SQLite with tmpdir pattern (matching `replayCache` test approach); no MSW needed (git ops mocked via `execGit` injection)
**Target Platform**: macOS and Windows desktop companion (Tauri v2 + bundled Node.js sidecar)
**Performance Goals**: Worktree creation completes within 2 seconds; poll adds <5ms overhead per cycle; drift evaluation is synchronous and adds <1ms per file observation
**Constraints**: 100% line/function/branch/statement coverage; `noUncheckedIndexedAccess`; `exactOptionalPropertyTypes`; no new runtime dependencies; git terminology blocklist enforced in all UI strings
**Scale/Scope**: Single-user desktop companion; initial pilot with 3–5 users across 1–3 repositories

## Work Packages

### WP01 — `packages/session-manager`: Core Store & Worktree Operations

**Scope**: TaskBranch SQLite store, worktree creation/removal/health-check, mission label inference, startup integrity scan.

**Modules**: `taskBranchStore.ts`, `worktreeManager.ts`, `missionInferrer.ts`, `index.ts`, `package.json`

**Key behaviors**:
- `openTaskBranchStore(dbPath)` — factory returning `TaskBranchStore` with full CRUD
- `createWorktree({ repoPath, missionSlug, sessionDate })` — `git worktree add` with name collision handling
- `removeWorktree(worktreePath)` — `git worktree remove --force`
- `isWorktreeHealthy(worktreePath, repoPath)` — checks presence in `git worktree list`
- `inferMissionLabel(filePaths)` — derives a human-readable slug from path segments
- Startup scan: iterate all non-deleted task branches, call `isWorktreeHealthy`, transition broken ones
- State transitions: `applyStaleThreshold`, `detectMerged` (checks `git branch --merged <default>`)

**Test approach**: Real SQLite with tmpdir; `execGit` injected as a spy returning fixture outputs; no live git required for unit tests.

**Contracts**: `contracts/session-manager.ts` — `TaskBranchStore`, `WorktreeManager`, `ExecGit`

**Acceptance**: US-1 scenarios 1,3; US-3 scenario 1,2; US-4 scenarios 1-3; US-5 scenarios 1-3; FR-001, FR-006, FR-013, FR-015, FR-016, FR-017

### WP02 — `packages/session-manager`: File Modification Detection

**Scope**: IPC hook handler (`session.fileModified`), `git status --porcelain` polling fallback, deduplication between hook and poll, sidecar registration.

**Modules**: `fileModificationDetector.ts` (in `packages/session-manager`); `services.ts` modification in `apps/desktop-companion`

**Key behaviors**:
- `FileModificationDetector.handleIpcEvent()` — called when sidecar receives `session.fileModified`
- `FileModificationDetector.startPolling(repoPath, sessionId)` — starts 10s interval running `git status --porcelain`
- `FileModificationDetector.stopPolling(sessionId)` — clears interval on session end
- Deduplication: if IPC event fires for a session within the same poll window, skip that poll result
- `SessionManager.onFileModification()` — receives events from detector; in managed mode, calls `WorktreeManager.create` if no task branch exists for the session

**Test approach**: `vi.useFakeTimers()` for poll interval tests; IPC events via direct `handleIpcEvent()` calls; `execGit` spy for `git status` outputs.

**Acceptance**: US-1 scenarios 1, 3; FR-001; SC-001

---

### WP03 — `packages/drift-detector`: Heuristics Engine

**Scope**: Topic domain inferrer, 3-signal heuristics engine, DriftSignal generation, session state tracking, dismissal logic.

**Modules**: `topicDomainInferrer.ts`, `heuristicsEngine.ts`, `driftDetector.ts`, `index.ts`, `package.json`

**Key behaviors**:
- `TopicDomainInferrer.infer(filePath)` — keyword-to-domain lookup (8 domains + "other")
- `HeuristicsEngine.evaluate(state, thresholds)` — returns `DriftHeuristicResult` with per-signal exceeded flags and `thresholdsExceeded` count
- `DriftDetector.observe({ taskBranchId, filePath, sessionStartedAt })` — accumulates file observations, calls `HeuristicsEngine`, generates `DriftSignal` when thresholds crossed, respects dismissals
- `DriftDetector.dismiss(signal)` — records fingerprint, prevents re-prompt for same signal
- `NoOpDriftConfirmer` — v1 stub always returns `null`

**Test corpus** (defined here per SC-002):
- "Should fire" scenarios (10): single-topic sessions that genuinely span 3+ dirs; sessions that hit time threshold; sessions that hit both directory and domain thresholds
- "Should not fire" scenarios (5): coherent multi-dir feature work (frontend + backend + tests = same feature); dismissed signal not re-fired; fresh session under all thresholds

**Test approach**: Pure unit tests; no I/O; `vi.useFakeTimers()` for elapsed time tests.

**Contracts**: `contracts/drift-detector.ts` — `DriftDetector`, `DriftConfirmer`, `DriftThresholds`

**Acceptance**: US-2 scenarios 1-7; FR-003, FR-004, FR-005; SC-002

### WP04 — Sidecar Wiring & Drift Integration

**Scope**: Wire `packages/session-manager` and `packages/drift-detector` into the companion sidecar lifecycle. Connect drift signals to sidecar notification channel (Tauri event emission). Register mode get/set IPC methods.

**Modules**: `apps/desktop-companion/src/sidecar/sessionWiring.ts` (new), `services.ts` (modified)

**Key behaviors**:
- `createSessionWiring(deps)` — factory: creates `SessionManager` and `DriftDetector` instances, registers `session.fileModified` in sidecar, wires `DriftDetector.observe()` into `SessionManager.onFileModification()`, emits `state.driftSignal` Tauri event when signal generated
- `session.fileModified` JSON-RPC method: calls `detector.handleIpcEvent()`, then `sessionManager.onFileModification()`
- `session.resume` / `session.delete` / `session.list` IPC methods registered
- `session.getMode` / `session.setMode` IPC methods
- Advisory mode: `session.fileModified` received but `sessionManager.onFileModification()` skips worktree creation; drift observation still runs (for advisory suggestions)
- Shutdown: `stopPolling` for all active sessions in `SIGTERM`/`SIGINT` handlers (following `controlPlaneWiring.ts` pattern)

**Test approach**: Mock `SessionManager` and `DriftDetector` via vi.mock; assert IPC method registration and event emission.

**Acceptance**: US-5 scenarios 1, 6, 7; US-6 scenarios 1-4; FR-008; SC-005

- Mode toggle (managed/advisory) in page header — calls `session.setMode`, shows "affects new sessions only" note

**Test approach**: Vitest + React Testing Library; IPC calls mocked; Tauri events mocked via `useTauriEvent` test doubles.
