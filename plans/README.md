## Why This Order

The production sidecar IPC registration gap is the highest-leverage correctness issue. UI routes invoke commands that proxy to sidecar methods, but production startup registers only a subset of the method families. Some tests explicitly tolerate `method not found`, which makes the failure easy to miss.

The Vitest discovery issue comes next because the current unit test command runs duplicated workspace tests through `node_modules`, creating noisy and misleading verification. Fixing discovery makes every later gate faster and more trustworthy.

The UI typecheck and coverage plan is third because it broadens the actual protected surface. It depends on sane test discovery first.

The GitHub CI plan is fourth because `package.json` defines `pnpm ci` to include integration tests, but the workflow currently runs only typecheck and coverage.

The docs plan is fifth. It matters for operator trust and handoff quality, but it should not outrank runtime wiring or verification gates.
